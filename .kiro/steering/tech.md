# Tech Stack and Rules

## Stack

| Layer | Technology |
|-------|-----------|
| UI framework | React 19 + TypeScript (strict) |
| Build tool | Vite 5 |
| PWA | vite-plugin-pwa (service worker, manifest, offline caching) |
| Local storage | Dexie.js (IndexedDB wrapper) |
| Internationalization | i18next + react-i18next (English + Urdu, RTL) |
| Styling | Tailwind CSS v4 via @tailwindcss/vite |
| Testing | Vitest + fast-check (property-based tests) |
| Monorepo | npm workspaces |

## Architecture Rules

### Data access

All data access goes through `@skeleton/core`. Apps use `createStore`, `deriveState`, `createSyncEngine`, and the `InMemorySyncAdapter`. Apps never call IndexedDB, Dexie, or the network directly. If a data utility would be useful to both apps, it belongs in `packages/skeleton`, not in an app.

### Records are append-only

Records are never edited or deleted. Mistakes are fixed by appending a reversal record (e.g. `EntryReversed`). Current state is derived from the record log using `deriveState` with an app-supplied reducer. This makes sync idempotent — two devices can never conflict on the same record.

### IDs

Use UUIDs (v4), generated by the Store's `add` method. Never use auto-increment ids — they break across devices and sync.

### Money

Store all money as integer paisa (1 rupee = 100 paisa). Never use floats for money. Convert to rupees only at display time, with thousand separators. This prevents rounding errors in balances and reports.

### Internationalization

Every user-facing string uses i18n keys defined in both `en.json` and `ur.json`. Skeleton-level keys (sync status, language toggle) are in `packages/skeleton/src/i18n/locales/`. App-specific keys are registered via `registerAppTranslations()` at app startup. Skeleton keys take precedence — app keys cannot overwrite them. Apps use `useTranslation` re-exported from `@skeleton/core`; they never import `react-i18next` or `i18next` directly. Numeric inputs accept Urdu digits (use `parseWholeRupees`, `normalizePhone`). Dates are local calendar dates (`todayISO()`), never `toISOString().slice(0, 10)`, which gives the UTC day.

### RTL and Tailwind

Use Tailwind logical properties for all spacing and alignment:

| Use | Don't use |
|-----|-----------|
| `ms-*`, `me-*` | `ml-*`, `mr-*` |
| `ps-*`, `pe-*` | `pl-*`, `pr-*` |
| `text-start`, `text-end` | `text-left`, `text-right` |
| `start-*`, `end-*` | `left-*`, `right-*` |

Logical properties automatically flip for RTL. Physical properties do not.

### TypeScript

Strict mode is on. No `any` in app or skeleton code. Use proper generic types that flow from app-defined payload interfaces through storage, sync, and state derivation. Use `type` (not `interface`) for collection definitions so generic constraints resolve cleanly.

### Testing

Business logic (ledger math, balance derivation, sync convergence) must have property-based tests using fast-check. These tests prove invariants hold for arbitrary inputs, not just hand-picked examples. Unit tests cover specific scenarios (i18n switching, phone validation, etc.).
